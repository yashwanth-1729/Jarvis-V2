# JARVIS 3.0.0

Release date: 2026-09-10

## Systematic Memory Generation

JARVIS 3 is a generation upgrade centered on how the assistant remembers,
retrieves, corrects and forgets information. Memory is now a coordinated local-first
system rather than a list of recent text rows.

- Six distinct roles cover working, episodic, semantic, procedural, prospective
  and reflective memory.
- Markdown bodies with portable front matter preserve readable full text while
  carrying lifecycle state, confidence, importance, provenance, validity, tags,
  pinning and correction history.
- Retrieval ranks only memories relevant to the current request, protects active
  procedures and reduces duplicate context before it reaches the model.
- Explicit memories become active immediately. Inferred high-signal information
  waits for review, and temporary working memory expires automatically.
- Corrections supersede old knowledge without losing bounded history. Named tool
  actions remain available for episodic recall without polluting long-term memory.
- Desktop maintains a generated Markdown vault while SQLite remains authoritative;
  Android keeps IndexedDB ownership and the existing sync/tombstone protocol.

## Compatibility

Existing memory text is migrated losslessly into the Markdown representation.
The existing Supabase memory columns remain valid, so this release does not need
a remote memory-schema replacement. Tasks, schedules, notes, voice behavior,
language choice, dynamic voice surfaces and deletion safeguards keep their current
contracts.

## Release identity

The backend health API, frontend package, Tauri desktop package and Android package
all report `3.0.0`. Android derives build code `3000000` from that semantic version.

## Validation

The isolated memory suite passed 15 checks, records passed 46, backend sync passed
39, and Python compilation, TypeScript and the production native web build passed.
The ARM64 Android package was built, installed without clearing app data and
launched on the connected phone. A separate frontend sync runner could not start
because the Windows host returned `uv_os_get_passwd ENOMEM`; that failure happened
before the test loaded.
